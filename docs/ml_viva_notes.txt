Q1. Why is this a regression problem?
--------------------------------------
Congestion Level is a continuous numerical variable ranging from 0% to 100%.
Since the target variable is a real-valued output (not a category), predicting
it requires a regression model rather than a classification model. We are not
assigning a label (e.g., "High" / "Low") — we are estimating the exact
percentage value of congestion for a given set of traffic conditions.

Q2. Why Linear Regression?
----------------------------
Linear Regression is used as the baseline model because:
- It is the simplest, most interpretable regression algorithm.
- It establishes a performance benchmark that all other models must beat.
- It assumes a linear relationship between features and the target, which
  may capture some of the straightforward relationships (e.g., higher traffic
  volume => higher congestion).
- Fast to train and requires no hyperparameter tuning.
If more complex models cannot significantly outperform it, Linear Regression
would be the preferred choice for its simplicity and interpretability.

Q3. Why Random Forest?
------------------------
Random Forest is selected as the primary model because:
- It is an ensemble method that builds multiple decision trees and averages
  their predictions, reducing variance and overfitting.
- It handles non-linear relationships and feature interactions well.
- It is robust to outliers and does not require feature scaling.
- It provides built-in feature importance scores via Gini impurity, enabling
  interpretability of which features drive congestion.
- With n_estimators=200 and random_state=42 for reproducibility, it achieves
  stable, high-accuracy predictions on tabular traffic data.

Q4. What is R² Score?
-----------------------
R² (R-squared), also called the Coefficient of Determination, measures how
well the model explains the variance in the target variable.
- Range: 0.0 to 1.0 (1.0 = perfect prediction)
- Formula: R² = 1 - (SS_res / SS_tot)
  where SS_res = sum of squared residuals, SS_tot = total variance in y.
- R² = 0.9653 (Random Forest) means the model explains 96.53% of the
  variation in congestion level.
- R² = 0.9180 (Linear Regression) means it explains 91.80% of variation.

Q5. What is MAE?
-----------------
MAE (Mean Absolute Error) is the average of the absolute differences between
actual and predicted values.
- Formula: MAE = (1/n) * sum(|y_actual - y_predicted|)
- It is expressed in the same units as the target variable (percentage points).
- Less sensitive to outliers than RMSE.
- Random Forest MAE = 2.8543 means predictions are off by ~2.85 percentage
  points on average. Linear Regression MAE = 5.3636 percentage points.

Q6. What is RMSE?
------------------
RMSE (Root Mean Squared Error) is the square root of the average of squared
differences between actual and predicted values.
- Formula: RMSE = sqrt((1/n) * sum((y_actual - y_predicted)²))
- Penalises large errors more heavily than MAE.
- Random Forest RMSE = 4.3355 means the typical prediction error is ~4.34
  percentage points. Linear Regression RMSE = 6.6590 percentage points.
- A lower RMSE indicates better model performance.

Q7. Which model performed better?
-----------------------------------
Random Forest Regressor significantly outperformed Linear Regression across
all three evaluation metrics:

  Metric     Linear Regression   Random Forest   Improvement
  ---------  ------------------  --------------  -----------
  MAE        5.3636              2.8543          ~47% better
  RMSE       6.6590              4.3355          ~35% better

Random Forest is the better model for this dataset, likely because it
captures the non-linear interactions between features like traffic volume,
environmental impact, and road capacity utilization.

Q9. Why did you use train-test split?
---------------------------------------
Train-test split is fundamental to supervised machine learning for the
following reasons:
- Training set (80% = 7,148 records): Used to fit the model parameters.
- Test set (20% = 1,788 records): Held out during training and used only
  to evaluate generalization performance on unseen data.
- Without this split, we would have no way to detect overfitting — a model
  that memorises training data but performs poorly on new data.
- random_state=42 ensures reproducibility (same split every run).
- An 80/20 split provides a large enough training set while maintaining a
  statistically significant test set for reliable metric estimation.

Q10. What are the limitations of the model?
---------------------------------------------
1. Daily Granularity: The dataset contains daily observations, not hourly.
   The model cannot predict peak-hour congestion spikes (e.g., 8 AM vs 3 PM).

2. Static Snapshot: The model predicts congestion based on static daily
   aggregates. Real-world systems need streaming, real-time data feeds.

3. Potential Data Leakage Risk: Features like environmental_impact are
   mathematically derived from traffic_volume and speed. These correlated
   engineered features inflate R² and may overstate predictive power.

4. Limited Geographic Scope: The dataset covers only 8 areas in Bengaluru.
   The model may not generalize to other cities or unmapped corridors.

5. No Temporal Modeling: This is a standard regression model (no LSTM, ARIMA,
   or time-series awareness). Temporal dependencies between consecutive days
   are not captured.

6. No Cross-Validation: A single train-test split was used. K-fold cross-
   validation would provide a more robust estimate of generalization error.

7. Class Imbalance in Congestion Range: Congestion levels cluster near 90%+
   for most records. The model may underfit rare low-congestion scenarios.
